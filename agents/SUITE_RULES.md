## 套件通用规则（由 suite-contract 同步，请勿在此手改）

- 套件文档均为只读副本，位于 `docs/suite/`：`SUITE_INTEROP.md`（设计）、`decisions/`（编号决策记录，说明设计为何如此）、`OPEN_QUESTIONS.md`（尚未裁决的问题）。涉及套件的任务前先读这三者；发现设计与决策记录不一致时停下来报告，不要自行选择。
- 涉及 `OPEN_QUESTIONS.md` 中尚未裁决的事项，不要实现，先询问。
- 本产品必须能独立完整运行。连接只做加法：任何核心功能都不得依赖对端产品、host 或 suite-contract 的运行时存在。
- 跨产品通信只走 suite-contract 定义的协议；消息结构以其 JSON Schema 和生成的类型为准，不得手写与 Schema 不一致的结构。
- 不得直接读写其他产品的数据库或存储。
- 业务代码只通过能力查询判断增强功能是否可用；依赖能力的 UI 在能力不可用时不渲染（设置页的连接面板除外）。
- 协议或契约有疑问时，不要自行修改约定，在 `docs/PROGRESS.md` 的"套件待决问题"中记录并询问。
- `privacy=private` 的数据永不进入任何出境通道（MCP、云 AI、同步、导出给第三方）。
- 每次涉及套件的改动，完成前都要验证"对端未安装/不可达"场景下行为与改动前一致。
